# How other tools do daily tasks and the daily rhythm

Read on 26 November 2026 from each product's own pages, for [spec.md](spec.md). Where a page
did not say something, this file says "not stated" rather than guessing.

| Tool | What it does | Source | Take or avoid |
| --- | --- | --- | --- |
| Things 3 | Today is "the list for to-dos that you want to start before the day ends". A start date "merely indicates the day on which you want to begin work"; future items "hibernate in Upcoming" and "automatically move over to Today". A deadline is a separate flag. This Evening is a section at the bottom of Today. Unfinished items are rescheduled by hand | [Today](https://culturedcode.com/things/support/articles/4001304/), [start dates and deadlines](https://culturedcode.com/things/support/articles/2803579/) | **Take:** day and due as two fields (T-7); items move into Today by themselves. **Differ:** we roll over automatically (PRD D-3) but count it (R-13, R-14) |
| Todoist | "While dates schedule when you plan to work on a task, deadlines represent the hard cutoff." Natural-language dates in the quick-add field | [Deadlines](https://www.todoist.com/help/articles/introduction-to-deadlines-in-todoist-uMqbSLM6U), [dates](https://todoist.com/help/articles/205325931) | **Take:** the same split. **Avoid:** a date parser of our own; the model resolves dates in both languages |
| Sunsama | A guided planning ritual (its "five Ps": process yesterday, plan, prioritise, prepare, publish), now drafted by an agent from connected tools in "2–4 minutes". A shutdown time is a setting; planning near it warns "You're out of time today". The review shows "judgement calls" with undo | [Planning and shutdown](https://www.sunsama.com/features/daily-planning-and-shutdown), [daily planning](https://help.sunsama.com/docs/usage-guides/daily-planning) | **Take:** "Yesterday" in the morning card; an evening close with one-key choices; undo instead of confirm. **Avoid:** a multi-step ritual each morning; ours is one card read in seconds. Workload warnings and roll-over details: not stated on the pages read |
| Linear | Issues can be marked "related, blocking, or blocked" | [Issue properties](https://linear.app/docs/issue-relations) | **Take:** the words "blocked by" and a plain graph of links (T-6). What Linear shows when a blocker closes: not stated on the page read |
| GitHub Issues | "Issue dependencies let you define issues that are blocked by, or blocking, other work"; blocked issues show a "Blocked" icon | [Issue dependencies](https://docs.github.com/en/issues/tracking-your-work-with-issues/using-issues/creating-issue-dependencies) | **Take:** same model, so a local task can be blocked by a mirrored GitHub issue (R-12) |
| Motion | Auto-scheduling "arranges tasks on your calendar based on priority, deadlines, duration, and dependencies" and re-plans as things change | [Auto-scheduling](https://www.usemotion.com/help/time-management/auto-scheduling/concept-auto-scheduling) | **Avoid:** auto-scheduling into the calendar; it needs an estimate per task and rewrites the calendar. A non-goal |
| `croner` (Rust) | MIT. Cron expressions in any zone; on the spring-forward day fixed-time jobs run "at the first valid second/minute", on fall-back "only once" | [croner-rust](https://github.com/hexagon/croner-rust) | **Take:** the same daylight-saving rule. **Not now:** the crate itself; three schedule shapes do not need cron syntax (T-8) |

Not checked: Akiflow, Reclaim and Amie, which work in the same space; Apple Reminders' new
"Today" behaviour in macOS 26. Worth a look before the app slices, for the card's copy.
