## How to read the chunks

- **Size** follows `CONTRIBUTING.md`: S goes straight to a failing test, M writes `AC-n` in its
  issue, L writes `specs/<issue>-<slug>/spec.md` and waits for the owner's approval.
- **Touches** names the code a chunk changes, so two threads that would edit the same files are
  not started together.
- Every chunk ends in its own pull requests, with local checks passing on the owner's Mac.

## Order

1. **Start now, in parallel:** P1-A, P2-1, P2-5 and P2-8. They touch separate code: scripts and
   results; a new eval tool; a new window; bundle config. P1-D is a five-minute change any thread
   can take.
2. **Next:** P1-B once the owner chooses; P2-2 when P2-1 lands; P2-6's research and spec; P2-4
   once the pill polish settles.
3. **Then:** P2-3, which builds on P2-2 and the provider settings.
4. **Last:** P2-9, after both gates.

`CLAUDE.md` says a phase starts only after the gate of the one before it passes. The owner asked
on 26 November 2026 to work on phases 1 and 2 in parallel, and to design the Google connector and
tasks (phase 4) early, so this plan lets that work be designed and merged now; the first public
release (P2-9) still waits for both gates.
